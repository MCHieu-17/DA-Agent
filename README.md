# Data Analysis Agent

LangGraph agent for CSV/XLSX analysis with a tool-first workflow.

## Workflow

`extract_schema/profile -> chat | analysis -> plan -> tool-first execution -> E2B Python fallback -> synthesis -> validation -> cleanup -> final answer`

CSV files and every worksheet in an XLSX file are profiled into a data catalog. Standard exploration, DuckDB read-only queries, aggregations, and static charts run through deterministic tools. Python generated by an LLM runs only in E2B and is never executed in the host process.

## Setup

1. Install dependencies: `python -m pip install -r requirements.txt`.
2. Copy values from `.env.example` into `.env`, including an LLM key and `E2B_API_KEY` for Python fallback.
3. Configure runtime limits only in `.env`; `configuration.py` is no longer used.

E2B is created only when the selected tool cannot fully satisfy a step and generated Python is required. It uploads the input files once per analysis request, disables outbound internet by default, downloads artifacts to `artifacts/{run_id}`, and closes the sandbox at completion.

The public graph output is `final_answer`. Synthesis writes and revises that answer directly; only validated analysis Q&A turns are retained in state for follow-up questions.

Analysis answers use a single Markdown string. Verified chart values accompany chart artifacts in synthesis context, and artifact codes are resolved to Markdown images or download links. The paths in those links are local artifact paths; a serving backend must map them to accessible URLs before showing the answer to remote clients. Run `PYTHONPATH=. python scripts/evaluate_synthesis_prompts.py` to compare the previous and current synthesis prompts on five Vietnamese scenarios with the same configured model.

## Tests

Run `python -m pytest -q --basetemp artifacts/.pytest_tmp` on Windows environments where the system temp directory is restricted.
